# Experiment 29: the exact list of writes, run on the local chain

**Status: pre-registered 2026-11-06,** before the runner was written or any case was run. This
experiment runs `exp-frames` experiment 58's cases on the local chain, with `writes` from
`docs/simulated-writes.md`. **The predictions are experiment 58's** and are not restated or
changed here: its README at `a629da4`, "Predictions" and amendment 1. This README fixes only how
the run executes them. Results are added below, and nothing above them is edited after a run.

## The question

Experiment 58's claim: a wallet that compares a transaction's exact list of writes, simulated
before signing, against an intent the user picks from templates, catches every harmful case
without a model. What would show it wrong: an attack whose list of writes equals a harmless
transaction's. This run gives the cases a chain to be simulated on.

## What is run, at which commits

- **The cases:** `exp-frames` at `a629da4`, `experiments/58-write-list/cases/`, regenerated by
  `npx tsx experiments/58-write-list/cases.ts` and checked byte for byte against the committed
  files before the run. There are 45 cases, 41 of them runnable on the local chain. The four
  fixtures are hand-written and are not run here.
- **The checker:** kohaku-rs at `b9713ec`, crate `frame-intent`, binary `write-check`, built
  `--release`.
- **The chain:** the local ethrex, at the test network's commit `64b8fc09d`, with
  `ethrex-8288.patch` and `scripts/ethrex-writes.patch`. Its genesis is experiment 58's
  `genesis-alloc.json` (41 accounts), at chain id 8141.
- **Keys:** this is not a post-quantum run. The cases are signed with secp256k1 test keys derived
  from public labels (`keys.json`), unlike the local chain's post-quantum runs, where genesis funds
  leanSPHINCS accounts so that no classical signature appears.

## Method

1. **Every runnable case gets a verdict before signing.**
   - `write-check --rpc <local chain> --raw <raw> --layouts layouts.json --template <t>
     --param ... --rules <rules>` is run against the genesis state, with `--sign` for a
     provisional case and `SIGNER_KEY` set to `keys.json`'s owner key.
   - The verdict, the matched, exempt, unlisted, missing and mismatched writes, and both
     encodings of Q are recorded.
   - **Nothing is sent for experiment 27's and 28's cases.** Many share a sender and a nonce
     key, so sending one would invalidate the others. Each is judged against the same genesis
     state.
2. **The signed passes are sent.** Each case on its own `ControlAccount` that passes is signed
   with Q in the batch form, sent, and its receipt recorded. This checks that the chain's re-check
   at inclusion agrees with the verdict at signing.
3. **The revert share.** For H1 (a token transfer) and H2 (an ether transfer), at each
   $p \in \{0, 0.25, 0.5, 1\}$, eight trials:
   - the honest transaction at the next nonce is simulated and signed with `write-check --sign`;
   - with probability $p$, from a generator seeded with the trial's number, the noise sender's
     transfer to the same recipient is sent and mined;
   - the signed honest transaction is sent, and its status recorded.

   The share is the fraction mined with status 0.
4. **Scoring.** Each verdict is set against experiment 58's predicted verdict for that case. A
   mismatch is reported as a mismatch, with the writes that made it.

## Deviations

1. **Run 2, after run 1 and before it ran.** Experiment 58's amendment 2 (`83996e9`) diagnosed run
   1's seven mismatches:
   - **The two E batches:** its prediction was wrong and the case is right. They are not rerun.
   - **Four of experiment 27's vectors:** a genesis defect. Their recipient did not exist, so each
     transfer needed state gas its frame did not have. The new genesis funds the recipient, and
     `cases.json` is byte-identical.
   - **`deploy-first`:** the vector was built for the test network's 500,000 `VERIFY` budget.

   **What runs.** At `exp-frames` `83996e9`, with `write-check` unchanged (`b9713ec`):
   - `with-expiry`, `keyed-nonces`, `legacy-nonce-7` and `value-and-default`, on the new genesis
     at the local chain's default 100,000;
   - `deploy-first` alone, on a second chain at the test network's 500,000. This is a stated
     deviation from EIP-8141's 100,000. Under 100,000, run 1's `not simulated` stands.

   No other case and no revert-share trial is rerun, and run 1's record is unchanged. The
   predictions are experiment 58's, unedited.

## Results, run 1 (2026-11-06)

**The record:** [`results/1-first.json`](results/1-first.json), from commit `4a6a847`.
- **Command:** `npx tsx experiments/29-the-exact-list-of-writes-on-the-local-chain/run.ts 1-first <exp-frames at a629da4> <write-check at kohaku-rs b9713ec>`.
- **The cases:** `cases.ts` regenerated them byte for byte before the run.
- **The chain:** ethrex `64b8fc09d` with both patches, chain id 8141, genesis from experiment
  58's `genesis-alloc.json`. The local chain's `VERIFY` budget is EIP-8141's 100,000.

**The verdicts, against experiment 58's predictions.** 34 of 41 runnable cases got their
predicted verdict.

| Family | Predicted | Got |
|---|---|---|
| Experiment 27's eight refused cases | `not simulated` | `not simulated`, all eight |
| Experiment 27's eleven valid cases | ten `pass`, `atomic-approve-swap` `fail` | five `pass`, `atomic-approve-swap` `fail`, four more `fail`, one `not simulated` |
| Experiment 28's twelve batches | ten `pass`, the two D `fail` (amendment 1) | eight `pass`, the two D `fail`, the two E `fail` |
| B0 to B6, C2 to C4 | B0, C2 and C3 `pass`; the other seven `fail` | all as predicted |

**The signed passes, sent.** B0, C2 and C3 were each signed with Q in the batch form and sent.
All three were mined with status 1, so the chain's re-check at inclusion agreed with the verdict
at signing.

**The seven mismatches.** None is a harmful case passing. In each, the checker refused a
transaction the prediction expected it to accept, and in each the refusal is correct on this
chain:
- **`with-expiry`, `keyed-nonces`, `legacy-nonce-7`, `value-and-default`, and experiment 28's two
  E batches.** Simulated on this chain, the body frame fails and the transaction reverts:
  - per-frame success for `with-expiry` is `[true, true, true, false]`;
  - for `keyed-nonces` and both E batches, `[true, true, false]`;
  - for `value-and-default`, `[true, true, false, false]`.

  So the writes the template expects never happen, and `write-check` reports each as missing. A
  transaction that will not do what the user asked is refused. Why the body fails on this genesis
  is a question for the cases' construction, and goes back to the experiment that built them.
- **`deploy-first`.** It is `not simulated`, with "prefix gas budget exceeded: 115600 > 100000
  (MAX_VERIFY_GAS)". The vector's validation fits the test network's 500,000 but not EIP-8141's
  100,000, which the local chain runs by default.

**The revert share.** Eight trials at each $p$, the noise transfer sent before the honest one
when the seeded draw fell under $p$.

| $p$ | H1, token transfer: reverted | Noise sent | H2, ether transfer: reverted | Noise sent |
|---|---|---|---|---|
| 0 | 0 of 8 | 0 | 0 of 8 | 0 |
| 0.25 | 1 of 8 | 1 | 0 of 8 | 2 |
| 0.5 | 4 of 8 | 4 | 0 of 8 | 4 |
| 1 | 8 of 8 | 8 | 0 of 8 | 8 |

H1 reverted exactly when the noise was sent: the batch form's final check re-reads the
recipient's token balance against its simulated value. H2 never reverted, because an ether
balance has no getter for that check. Both are as experiment 58 predicted: H1's share follows
$p$, and H2's is 0.

**What is not tested here:**
- the replay pair, which is fixtures only, and is where experiment 58 predicts the claim fails;
- experiment 34's pair, also fixtures only;
- the EIP-7906 encoding, since this chain has no mode 3.
